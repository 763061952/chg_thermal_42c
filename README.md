# 亮屏快充 · 稳充（chg_thermal_42c）

> 小米 / 红米 HyperOS 充电模块：解除有线充电的温控降档，把亮屏充电功率稳在可用区间，
> 避免"冲高 → 过热 → 被砍到 7~10W"的反复通断。v5 起带**机型适配表**与**温度保护**。

作者：酷安@happier2（GitHub [@763061952](https://github.com/763061952)）｜ 许可：**GPL-3.0** ｜ 适配：有 `xm_power` 节点的机型（HyperOS）

---

## 它解决什么问题

实测现象（Redmi K90 Pro Max，原装头 + 亮屏）：平稳快充 **46~55W**，电芯温度爬到 **~36℃** 后
官方策略开始写降档（`wired_ctrl_limit=11/12/14`、电流压到 4.5~6A），功率掉到 **7~22W**；
继续升温到 **42℃** 时输入电压从 17.9V 直降到 8.9V，功率只剩 **~4W**。

本模块在充电期间写 `wired_thermal_remove=1` 解除这层降档，把亮屏功率稳定在 **40~47W**；
同时用**温度保护**兜底，避免"解除温控后无人看管"。

## 原理

控制的节点：`/sys/class/xm_power/charger/charger_thermal/`

| 节点 | 作用 | 本模块 |
|---|---|---|
| `wired_thermal_remove` | `1` = 解除有线充电的温控降档；`0` = 交回官方 | ✅ 核心 |
| `wired_ctrl_limit` | 厂商温控档位（数值越大越保守，行 0~14 对应设备树 `wired_thermal` 表） | 视机型 |
| `wired_chg_curr` / `wired_chg_curr2` | 与档位联动的电流设定值 | ⬜ 未使用 |
| `wireless_*` | 无线充电对应节点 | ⬜ 未使用 |

`service.sh` 每 `POLL` 秒巡检：

```
机型识别 → devices/*.conf（未适配机型进入安全模式：不写任何节点）

Charging / Full 且 温度 < T_HARD   →  remove=1（+ 视机型写放开档）
温度 ≥ T_HARD                      →  remove=0 交回官方降温
温度 ≤ T_RESUME（迟滞）            →  重新 remove=1
其它状态 / 按钮关闭                →  remove=0 交回官方
```

温度读数为 `battery/temp`（0.1℃）；连续 3 次读不到温度也会保守交回官方。

### 为什么 K90PM 不写档位

在 K90PM（myron）实测：写 `remove=1` 后官方依然会写 `wired_ctrl_limit=11/12/14`，
但功率**不再跟随下掉**（稳定 40~47W）——即 `remove=1` 时该档位已被驱动架空
（0~100 任意值都能写进去、读得回，但不改变功率）。因此本机型只写 `remove`，
不再写"放开档"与官方策略做无效竞争。完整实验见
[`calibration/k90pm/FINDINGS.md`](calibration/k90pm/FINDINGS.md)。

## 支持机型

| 机型 | 系统 | 做法 | 温度保护 | 实测 |
|---|---|---|---|---|
| 2608BPX34C | HyperOS / Android 17 | 放开档 `3`（官方档 `12`） | 未标定（关闭） | 放开 38~43W ／ 官方 9~25W |
| Redmi K90 Pro Max<br>（`myron` / `25102RKBEC`） | OS4.0 / Android 17 | 只写 `remove=1`（档位被架空） | `T_HARD=430` / `T_RESUME=420` | 解除后 46~47W 稳充，43℃ 交回 / 42℃ 恢复（周期 ~2 分钟）；未解除时 36℃ 后掉到 7~22W、42℃ 掉到 ~4W |
| *（你的机型）* | | | | 按 [`机型适配指南.md`](机型适配指南.md) 标定后欢迎 PR |

**未在表中的机型 → 安全模式**：守护进程只记日志，不写任何节点。

## 安装

1. `sh build.sh` 生成 `dist/chg_thermal_42c-v5.0.0.zip`（或直接下载 Releases）
2. KernelSU / Magisk 里刷入，重启
3. 看日志：`/data/local/tmp/chg_fast.log`

## 配置

- 通用项：`config.sh`（巡检间隔 `POLL`，默认 2 秒）
- 机型项：`devices/*.conf`

| 键 | 说明 |
|---|---|
| `DEVICE_ID` / `DEVICE_MODEL` | 匹配 `ro.product.device` / `ro.product.model` |
| `OPEN_GEAR` / `STOCK_GEAR` / `WRITE_GEAR` | 是否写档位与档位值（K90PM：`WRITE_GEAR=0`） |
| `T_HARD` / `T_RESUME` | 温度保护阈值（0.1℃）；`T_HARD=0` = 关闭 |

改完重启生效，或杀掉守护让它重新拉起：`kill $(cat /data/local/tmp/chg_fast.pid)`。

## 关闭 / 卸载

- **临时关闭**：在模块目录建一个 `disable` 文件（KernelSU 里就是点按钮）→ 守护 2 秒内 `remove=0` 并退出
- **卸载**：`uninstall.sh` 自动停守护 → `remove=0` → 清日志
- 档位不主动回写：交回官方后由官方策略自行接管（实测官方的写法是动态的，不该由模块固化）

## 已知限制（重要，先看这里）

1. **温度保护是兜底，不是精密温控**：2 秒巡检 + 0.1℃ 分辨率的开关式控制，
   实测升温速率约 0.05℃/s，最多过冲 0.1~0.2℃。阈值可在 `devices/*.conf` 调整。
2. **`remove=1` 期间电芯保护依赖原厂驱动**：模块只是不参与降档，不修改任何电芯保护参数。
   出现烫手、异常先拔线。
3. **"功率掉到 0"是正常瞬断**：PD/PPS 每次切换电压档（8.9V ↔ 16~18V / 5V）都会出现约 0.4W 的
   瞬断再爬升，息屏/亮屏切换时尤其明显（实测记录见 FINDINGS §5），与模块无关。
4. **节点不存在会直接退出**（`[ -w ... ] || exit 1`），不会在不支持的机型上乱写。
5. 档位含义因机型而异，**不能抄别的机器的数字**；K90PM 与 2608BPX34C 的机制本就不同。
6. **高负载场景（游戏 / 烤机）温度保护能力有限**：此时温度主要来自 SoC，
   模块能做的只是交回充电功率，压不住 SoC 自身发热
   （实测烤机 + 快充时电芯可到 45℃+）。这是物理限制，不是模块能解决的。
