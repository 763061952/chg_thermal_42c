# K90PM（Redmi K90 Pro Max）标定记录

- 日期：2026-10-07
- 设备：Redmi K90 Pro Max，`ro.product.device=myron`，`ro.product.model=25102RKBEC`
- 系统：Android 17 / `OS4.0.0.33.XPMCNXM`，内核 `6.12.69-android16`
- 充电驱动：`mca_charger_thermal`（OF 节点 `/soc/mca_charger_thermal`）
- 条件：原装充电器、亮屏、电量 20%~36%、Root（KernelSU）
- 数据：`logs/observe_1007_224129.log`（官方基准）、`logs/observe_1007_224902.log`（切屏测试、1s 采样）

## 1. 节点

`/sys/class/xm_power/charger/charger_thermal/` 下：

| 节点 | 权限 | 说明 |
|---|---|---|
| `wired_ctrl_limit` | `rw-rw-r-- system system` | 温控档位；驱动不做范围夹取（0~100 均可写入并读回） |
| `wired_thermal_remove` | `rw-rw-r-- root root` | `1` = 解除有线温控降档 |
| `wired_chg_curr` / `wired_chg_curr2` | `rw-rw-r-- root root` | 与档位联动的电流设定值（µA 量纲） |

注意：`wired_ctrl_limit` 属主是 `system:system`。用 `adb shell`（shell 用户）直接重定向写入会 `Permission denied`，
必须让 root 执行整条命令（例如 `su -c "sh -c 'echo 0 > \$NODE'"`），否则会出现"写入静默失败"的假象。

## 3. 官方行为（remove=0，原装头 + 亮屏）

- 平稳快充：`limit=0`、`wired_chg_curr≈18.4A`，电池侧 46~55W（17.8V 输入侧）
- 温度 ≥ ~36℃：官方开始写 `limit=11/12/14`，`curr` 被压到 4.5~6A，功率掉至 **7~22W**
- 温度 ≥ 42℃：输入电压从 17.9V 直降到 ~8.9V，功率掉到 **~4W**（官方强降温）
- `limit` 由官方策略（`mca_charger_thermal_handle_limit`）动态写入，不是固定值

## 4. 关键实验：remove=1 的效果

在 34.9℃、46W 状态下写入 `remove=1` + `limit=0`：

| 时间 | limit（官方仍会写） | 功率 | 温度 |
|---|---|---|---|
| +12s | 0 | 47.1W | 34.9℃ |
| +15s | 11 | 46.3W | 35.2℃ |
| +21s | 12 | 46.1W | 35.6℃ |
| +45s | 0 | 44.8W | 37.1℃ |
| +63s | 14 | 44.3W | 38.0℃ |
| +120s | 0 | 45.7W | 41.0℃ |

结论：

1. **`remove=1` 已经足以解除温控降档**——官方继续写 `limit=11/12/14`，但功率不再跟随下掉；
2. 即 `remove=1` 时 `wired_ctrl_limit` 被驱动架空（写 0~100 都能写进去但不改变功率），
   所以 K90PM **不需要**再写"放开档"（写档位只是与官方策略做无效竞争）；
3. 代价是温度会持续爬升：120s 内 34.9→41.0℃，继续到 42.5℃；
4. 因此 **K90PM 必须有温度保护**（本项目 `devices/myron.conf` 中 `T_HARD=420/T_RESUME=390`）。

## 5. 屏幕状态切换与"功率掉 0"

`logs/observe_1007_224902.log`（1s 采样，t=50s 息屏、t=100s 亮屏）：

- t=50s 息屏：输入从 8.77V → **15.9V** 重协商，功率瞬间 0.4W，1 秒后恢复 ~15W，随后爬到 22.5W；
- t=102~110s 亮屏：输入 8.92V → **5V** → 8.92V 重新谈判，低功率期约 8 秒；
- 其余多次（t=14/32/39/84/93）电压档切换同样伴随 ~0.4W 的瞬断。

结论：**"功率掉到 0"是 PD/PPS 电压档位重协商的正常瞬断**（每次 8.9V ↔ 16~18V 或 8.9V ↔ 5V 切换都会出现），
与是否使用本模块无关；模块守护循环按 2s 轮询该瞬断不影响控制逻辑（只写 remove，不依赖功率读数闭环）。

## 6. 适配参数（写入 `devices/myron.conf`）

```
SUPPORTED=1
WRITE_GEAR=0        # remove=1 时 limit 被架空，不写档位
T_HARD=430          # 43.0℃ 交回官方
T_RESUME=420        # 42.0℃ 重新放开
```

### 阈值怎么定出来的（实测循环，`logs/observe_1007_230020.log`）

| 阶段 | 时长 | 温度变化 | 功率 |
|---|---|---|---|
| 放开快充 | 78s | 41.0 → 43.1℃ | 46~47W |
| 触顶交回官方 | 47s | 43.1 → 42.4℃ | 官方 2~4W |
| 恢复放开 | 54s | 42.4 → 43.0℃ | 46~47W |

即周期约 2 分钟、快充占空比约 60%。教训：最初按"官方阈值"设 42.0℃/39.0℃ 过于保守——
官方限流下降温很慢，快充恢复需要等待数分钟，平均功率会掉到 10W 级别，等于白装。
最终采用 43.0℃/42.0℃（1℃ 迟滞）：43℃ 仍低于常见的 45℃ 电池保护线，且循环节奏可用。
